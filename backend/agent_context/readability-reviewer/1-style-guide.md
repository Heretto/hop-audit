# Style guide

Apply the site's own style guide when one is attached as a reference; this is the default.

- Write for the reader's task. Lead with what the reader does or gets, then the detail.
- Use the second person ("you") and the active voice. Name who acts in each step.
- One idea per sentence. Aim for 15–20 words on average; split anything over 30.
- One task per procedure, numbered steps, one action per step. Put the result of a step after the action, not before it.
- Use the UI's exact labels, in bold, and match their capitalization.
- Prefer common words: "use" not "utilize", "start" not "initiate", "help" not "facilitate", "so" not "in order to".
- Define a term the first time it appears, and use one term per concept throughout.
- Headings say what the section helps the reader do ("Publish a map"), not the feature name alone.
- Avoid "simply", "just", "easy" and "obviously": they read as dismissive when the reader is stuck.
